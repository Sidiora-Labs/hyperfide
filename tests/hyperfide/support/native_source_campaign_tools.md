Campaign preparation and observation
====================================

All configuration and outputs below are private regular files (0600). Preparation uses an already isolated HTTPS source service and never loads ambient `.env`.

Run with `SOURCE_CONTROL_SDK_MODULE_ROOT=/absolute/compiled/sdk HF_SOURCE_PREPARE_CONFIG=/private/prepare.json node tests/hyperfide/support/native_source_campaign_prepare.mjs`.

The preparation configuration contains `schema_version: 1`, `isolated_scope: true`, `endpoint`, exact three-field `scope`, `credential_file` (or `signed_config_file` for the native signed TLS client), `output_directory`, `backend_identity`, and optional `file_counts` (default 10000, 1000000, 10000000), `unique_contents` (1–1000), `history_depth` (1–1000), and `seed`. Credentials use the deployed workload credential format. Keep the same configuration/output directory for retries: the operation journal preserves operation identities across unknown outcomes. Changing preparation inputs in an existing journal fails.

Preparation creates actual immutable blobs/file descriptors, shared directory trees with at most 100 entries per directory, and acknowledged revision histories through public APIs. Every corpus contains the same ten `hot/file-NN.txt` edit paths. Paginated API traversal counts each subtree reference, avoiding expansion of repeated subtrees. `prepared-corpora.json` records the exact acknowledged revisions, logical counts, content cardinality, history, capabilities and machine identity. Copy its `corpora` into the private deployment configuration. The shared-content default is explicit; increase `unique_contents` for another measured profile rather than representing repeated content as unique bytes.

Before launching the dedicated source service, add `--import=/app/deploy/hyperfide/fleet-control/source-instrumentation.mjs` to its Node options. Set `HF_SOURCE_INSTRUMENTATION_LOG=/app/state/source-observer.jsonl`, `HF_SOURCE_INSTRUMENTATION_S3_ENDPOINT` to the actual storage origin, and `HF_SOURCE_CAMPAIGN_SCOPE` to its exact scope JSON. The preload requires a fresh log, measures real outgoing requests and consumed response bytes, excludes other origins, and records hashed object keys. Its streaming wrapper is part of the measured deployment and must remain enabled for all comparison sizes. It does not infer storage provider billing bytes or cache activity.

`native_source_campaign_collect.mjs` is a read-only collector. `HF_SOURCE_COLLECTOR_CONFIG` points to a private JSON containing `scope`, `pg_module` (absolute compiled pg module), `database_identity`, `backend_identity`, `storage_logs` (all process log paths across restarts), and `client_metrics_file`. `DATABASE_URL` must identify the dedicated database with read permissions. The collector uses a repeatable-read transaction for exact scoped revision count, pending metadata queue, pending publication age, and current database connection/lock-wait observations. The log must be available locally, or delivered by a protected deployment executor before collection.

The separately measured client metrics file must contain `schema_version: 1`, exact `scope`, recent `sampled_at`, descriptive `measurement`, and actual nonnegative integer `hydrated_bytes`, `cache_hits`, `cache_misses`. API-only profiles can record zero only when their executed path explicitly has no materialization or cache; mixed/virtual profiles must export real counters. Missing or stale evidence fails collection.

`native_source_campaign_observer.mjs` wraps a pinned collector executable for the campaign hook contract. Its private `HF_SOURCE_OBSERVER_CONFIG` includes `schema_version: 1`, `scope`, `backend_identity`, `collector_argv`, SHA-256 `collector_digest`, optional `env_keys`, and `timeout_seconds`. The collector emits exact scope, fresh `sampled_at`, `sources` provenance and `observations`. The wrapper validates all counters and preserves the raw collector response as hashed evidence next to the hook result. This wrapper alone does not qualify a campaign: the collector must run against actual deployment observations.

Run the instrumentation boundary regression with `node --test tests/hyperfide/support/native_source_campaign_instrumentation.test.mjs`. It makes real HTTP requests through the deployed preload, checks exact consumed bytes, checks unrelated-origin exclusion, and checks private object paths are absent from evidence.
